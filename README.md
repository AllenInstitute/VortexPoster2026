# A visual cortical column connectome — SfN 2026 poster as a web page

The poster, panel by panel, with captions and interactive versions of the
figures where turning a cell type on and off tells you something.

Built with [Quarto](https://quarto.org) from `index.ipynb`.

## Layout

```
index.ipynb        the page. All prose is in markdown cells — edit it here.
_quarto.yml        site config: title, nav, theme, TOC
custom.scss        the poster's teal, the stat row, the exemplar gallery
build_assets.py    exports data/ and figures/ from the parquet store
data/              ~300 KB of derived numbers. Committed.
figures/           web-sized copies of the poster panels. Committed.
sfn_2026_poster.pdf  the poster as printed, linked from the nav
```

## Rebuilding

Two steps, and only the first needs the connectome data:

```bash
../.venv/Scripts/python.exe build_assets.py   # writes data/ and figures/
quarto render                                 # writes _site/
```

`build_assets.py` reads two things from outside this folder: `../poster/` for
the modules and the plotted figures, and the supplement folder for the panels
this repository does not plot. The second is wherever you keep it:

```bash
POSTER_SUPPLEMENT="/path/to/sfn_2026_supplement" ../.venv/Scripts/python.exe build_assets.py
```

Without it the script looks for `../sfn_2026_supplement`, and if that is not
there it says so and leaves the existing `panel01`, `panel07` and `panel08`
images alone — they are committed, so a rebuild without the sources is safe.

`build_assets.py` is the only thing that imports the poster modules or reads
the parquet store. The notebook reads `data/` and nothing else, which is what
lets the page rebuild on a machine that has never seen the connectome — a
clone, or a GitHub Actions runner.

`quarto preview` while editing gives a live-reloading local copy.

## Publishing to GitHub Pages

The repository is `AllenInstitute/VortexPoster2026` and the page is served at
<https://alleninstitute.github.io/VortexPoster2026/>. Both are already set as
`repo-url` and `site-url` in `_quarto.yml`.

`quarto publish gh-pages` is the whole deployment:

```bash
quarto publish gh-pages
```

It renders locally and pushes `_site/` to a `gh-pages` branch, then sets the
repository's Pages source to that branch the first time. Nothing else to
configure, and no Actions workflow to maintain.

Note that `git` is not on this machine's PATH — GitHub Desktop bundles it at
`%LOCALAPPDATA%\GitHubDesktop\app-<version>\resources\app\git\cmd`, and the
PATH entry points at an older `app-` directory than the one installed. Add
the current one to PATH before running `quarto publish`, or run it from a
shell that has git.

If you would rather the page rebuild on push instead, `freeze: auto` means
the executed outputs are stored under `_freeze/`, which is committed — so a
runner can render without Python, the data or a Jupyter kernel.

## Editing

- **Text** lives in the markdown cells of `index.ipynb`. Nothing is generated
  from a template, so edit it directly.
- **Captions** for the interactive figures are the `#| fig-cap:` lines in the
  code cells.
- **Every figure is click-to-zoom** (`lightbox: auto` in `_quarto.yml`). The
  exemplar gallery's sixteen images additionally carry
  `group="exemplars"`, which makes them one set: click any one and the arrows
  step through all sixteen. To add a cell to that gallery, drop its PNG in
  `figures/` and add one more line to the `::: {layout-ncol=4}` block —
  it is plain markdown, not generated.
- **The soma plot is drawn at equal unit scale** — `scaleanchor` on the y axis
  with `constrain="domain"` on the x. That is what makes it tall and narrow,
  and it is deliberate: the column is 133 µm wide and 705 µm deep, so any
  other shape misreports it. Changing `height` alone keeps the scale honest;
  the width follows from it.
- **Colours and order** come from `data/palette.json`, exported from
  `arbors.MESO_INHERITED` so the interactive figures cannot drift from the
  static panels they sit beside.
- To add a panel, drop a PNG in `figures/`, add it to `COPIES` in
  `build_assets.py` if it comes from `poster/output/`, and reference it from a
  markdown cell.

`index.ipynb` was first generated by a script, but it is the source of truth
now — do not regenerate it over your edits.
